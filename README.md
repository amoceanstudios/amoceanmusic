# Motion Music

An original ink-blue character performs six scroll scenes, now expanded into the Jimmy companion with local tools and an optional server-side AI endpoint. Vite + TypeScript and one SVG rig; no framework or external fonts. The tour and local tools need no API key. AI requires private Netlify Functions configuration; dictation is explicitly optional.

## Run

```sh
npm install
npm run dev
```

Use Node.js 20.19+ or 22.12+. Open the address printed by Vite. `npm run build` checks TypeScript and creates `dist/`. `npm run preview` serves that production build. This project uses ES modules and needs the local server; it is not a double-click HTML export. The earlier standalone Jaimsee file outside this checkout is unchanged.

## The tour

1. Load: original ink-blue spin, settling squash, welcome, Enter hint.
2. Welcome: anticipation, dash, near-letter stop, recoil, spoken reassurance.
3. About: fall/landing, bone-attached book, three-sentence reading, page turn and closing snap.
4. Portfolio: the same rig enlarged for a close-up, “Go, look around!”, an arcing pullback, three plain cards.
5. Contact: the same body with suit and spring-driven mustard tie. Form validation and “sent” state are local; **no message is sent**. The email address is an intentionally non-deliverable `.example` demo address.
6. Bye: sad brows, eye highlights, one tear, shoulder shiver, shrinking atom.

Scroll backward to scrub the poses. Speech has a separate real-time playhead and finishes across section changes; pending scripted lines take priority over proactive assistance. Idle scene playheads give visitors time to see the beats without precisely scrubbing each frame. Enter is explicit; the page does not scroll itself on load.

## Animation implementation

- `src/rig/skeleton.ts`: one parented hierarchy, including arm and leg segments, folded ear, glasses, three-part note tuft, eyes and mouth. Pose data is `{boneId: {rot,sx,sy,tx,ty}}`.
- `src/clips/`: pose tracks, per-key easing and viewport-relative flight anchors. `src/scenes/director.ts` samples them in either direction.
- `src/physics/`: Catmull–Rom path, underdamped position springs, secondary joint springs, velocity stretch and DOM obstacle avoidance. Occluded anchors are projected into free space. Safety takes precedence over a continuous flight when readable content would be covered.
- Fixed logic/body animation at **24 Hz** with rAF presentation. Ear, tuft, glasses and tie springs are integrated in substeps for stability and interpolated at display refresh rate; body poses are not interpolated. Two brief SVG ghost exposures mark fast transitions.
- `src/rig/visemes.ts`: eight closed paths with 12 matching vertices, morphed over a logic frame. Scripted voice clips include phoneme tracks generated by the same local synthesizer as the audio. Lip-sync follows the actual AudioContext playback position, with a 25 ms visual lead. Silent text-only playback uses a two-frame lead.
- Reduced motion hard-cuts poses and disables flight, stretch, spin, ghosts, springs and lip movement; bubbles, forms and assistant actions still work.

## Change a line

Edit `src/lipsync/lines/<id>.json`: `text`, `duration`, and `cues: [{t, v}]`, with times in seconds. Supported visemes: `rest`, `MBP`, `AA`, `EE`, `OH`, `OO`, `wide`, `grimace`.

Generate a new cue track:

```sh
npm run cues -- "Your new line!"
```

This command generates a text-only approximation for a new line. For a matching recorded voice, regenerate with `python scripts/voices.py` after editing the text in the line JSON. That script needs local Flite shared libraries and ffmpeg, produces the compressed audio and measured phoneme timing, and updates `src/audio/voices.json`. None of these generation tools are needed to deploy the committed `dist/`. `node scripts/cues.mjs --seed` replaces the JSON with the earlier silent demo lines; do not run it to update recorded audio. New runtime replies use a local device voice when available and otherwise retain readable bubbles; shipped scripted and common assistant lines have bundled voice clips.

## Recolor Richie

Change only `src/rig/palette.ts`. All rig, prop and effect colors come from those tokens. The simple page styles live separately in `src/style.css`.

## Assistant rules

Add an object in `src/assistant/rules.ts` with an id, cooldown (at least 20 seconds), trigger and local action. Implement new action kinds in `src/main.ts`’s `execute` function and include an Undo action. `LocalBrain` implements the `AssistantBrain` interface in `src/assistant/brain.ts`; no LLM is connected.

Try these behaviors:

- Stay idle for 8 seconds after a scripted line: “Next one?” plus a Next button. It never scrolls without your click.
- Reverse scroll direction three times within four seconds: section mini-navigation.
- Hover/focus a portfolio card for more than 1.5 seconds: its one-line description.
- Leave an incomplete email field: a pointing prompt. Submit an empty message: the message field receives focus.
- Select page text: a Copy chip. The clipboard is written **only after clicking**; clipboard permission failure is announced. Undo dismisses the offer, not an already completed clipboard write.
- Reload: short welcome back and skipped spin, when localStorage is available.
- On narrow screens: smaller corner placement and an explanatory prompt.

Every proactive offer has Undo/Okay and a per-rule cooldown. Quiet parks Richie small and stops proactive actions. Click Richie or press `/` to ask; Escape closes the dialog. Commands include `go to about`, `read about`, `show work`, `contact`, `copy email`, `quiet`, `sound on/off`, and `help`. Minor single-edit section-name typos are accepted. Unknown input lists the supported commands. No personal data is generated or filled in, and no form submits automatically.

Audio starts muted and is enabled only by a user gesture. Visit count and mixer levels are saved locally; forms, selections and questions are not saved or transmitted. Voice clips are fetched only from the same origin as the site; there are no external audio services or APIs.


Tests exercise spring convergence/overshoot, paths and avoidance, mouth topology and cue ordering, rule cooldowns and quiet mode, reversible clip sampling, browser scene transitions, speech continuity, form validation/local submission/undo, mobile placement and copy offers. ## Deploy to Netlify from GitHub

The repository includes the prebuilt `dist/` site. Import `amoceanstudios/amoceanmusic` into Netlify and select `main`. The included `netlify.toml` sets the publish directory to `dist`, leaves the build command empty, and skips dependency installation. No Netlify build command is required.

After changing the TypeScript source locally, run `npm install` and `npm run build`, then commit the updated source **and** `dist/` files. Netlify publishes the committed output after each push. Connecting the repository to your Netlify account still requires your authorization in Netlify.

## Cinematic sound experience

Click **Start experience** to replay the tour with sound, or continue silently. The Sound button mutes **all** channels; M is its keyboard shortcut outside text fields. **Mix** controls master, music, voice and SFX levels independently and offers Replay experience. Headphones are useful for stereo movement.

- An original procedural score changes harmony and pacing across the six scenes, with sparse plucks, a soft bass foundation, stereo space and a resolving farewell. It is generated locally in Web Audio, not streamed.
- Richie has 24 bundled original synthesized voice clips. The Flite CMU RMS voice is transformed with pitch, tempo, EQ and compression; scene-specific delivery is brighter for the portfolio and gentler for About/Bye. This is a deliberately synthetic cartoon voice, not a human actor or celebrity imitation.
- The voice and phoneme track come from the same synthesis pass. The player uses the **actual audio sample clock**, waits for decoding before moving the mouth, and ducks the score underneath dialogue. The active line continues across section cuts.
- SFX follow clip thresholds and real velocity: spin, arc whoosh, landing, elastic recoil, book opening, turning and closing, tie rustle, reveal chimes, button/hover/focus/typing sounds, validation cues and success/copy feedback. Cooldowns avoid scroll-triggered noise storms.
- Background wind follows flight speed, effects are panned to Richie's horizontal position, and restrained visual rings/voice energy respond to those same events. Quiet score pulses are presented against the same scheduled audio beat times. Reduced motion removes flying/impact effects and visual pulses but keeps optional voice, score and interface feedback.
- Mix buses, gain ramps and a compressor control peaks. Hidden tabs suspend the audio clock and score scheduler.
- Voice files ship as Ogg with MP3 decoding fallback for browser compatibility. New dynamic text can use an installed **local** device voice; if none is available, the text bubble remains. No cloud TTS is invoked.

`src/audio/engine.ts` contains the score, synthesis and mixer. `beats.ts` maps clip progress to effects; `visuals.ts` implements sound-reactive visual accents; `ui.ts` handles opt-in and controls. `scripts/voices.py` is only an authoring tool. Flite is an open-source speech synthesizer from Carnegie Mellon (https://github.com/festvox/flite); its libraries are not bundled in the site.

Audio tests decode and play a real bundled clip in Chromium, measure voice activity, check dialogue/animation clock drift, verify ducking and mute, check every asset/phoneme track, and exercise UI sound feedback. Browser playback is verified; final mix preference remains subjective.

## Jimmy companion upgrade

Richie’s existing original rig and all 24 recorded voices, scene clips, music buses and mixer are retained. The expanded companion is named Jimmy in the new bag; the older tour controls retain the Richie label for compatibility. Click Jimmy or his gold bag, or press `/`. Drag the character to a preferred free area; text avoidance remains authoritative, so he may move away from a position that covers content. Minimize or Quiet turns him into a small portal; click it to restore him, even after the footer farewell.

Feature modules:

- `src/companion/tools.ts`: arithmetic parser (no eval), conversion and timer/reminder parsing, searchable categorized registry.
- `companion.ts`: bag UI, drag/minimize, portal entry, task poses/hand prop, local tools and explicit permission gestures.
- `ai.ts`: opt-in client, cancellation, timeout, section-only context.
- `netlify/functions/jimmy.mjs`: real server-side OpenAI Responses API route, task allowlist, bounded input/output, same-origin checks, access-code comparison and per-instance request throttling. It never receives the contact form or whole page automatically and never executes model-generated actions.

### Enable real AI on Netlify

In **Netlify → Environment variables**, add **JIMMY_AI_KEY** (your OpenAI API key, Functions scope) and **JIMMY_ACCESS_CODE** (a strong private access code). Optionally set **JIMMY_AI_MODEL**; default is `gpt-4.1-mini`. Redeploy so Functions receive the values. Never put the provider key in `VITE_*` variables, source, browser code, or chat. On the site, open AI/privacy, enable AI and enter only the access code. The access code stays in page memory. Provider usage can incur charges; set a provider budget. The in-memory limiter is per active function instance, not a durable global quota; the access code is required even if the provider key exists.

Without these server values, the route returns an explicit configuration error, not a pretend AI answer. Local calculator, notes, timers, files, clipboard and unit conversions work without AI. Open-ended conversation, translation, summarization, rewriting, spelling and image OCR use the configured endpoint. AI answers are not automatically executed. Plain `vite` has no Functions runtime; use deployed Netlify or Netlify Dev to exercise the real endpoint. A static-only zip cannot provide server AI.

### Tool behavior and limits

- Web search and image generation are explicit external shortcuts, not automated browsing or a built-in image model.
- Notes and reminder deadlines are stored locally. Undo restores the previous note or removes a newly created reminder; external clipboard writes and opened tabs cannot be undone by this page.
- Timers use absolute deadlines, show cancel controls and alert on resume. They do not run as an OS background service; keep the page open. Reminders support `over 20 min` or `morgen 09:00 | label` in the browser’s local timezone, plus `.ics` export for a calendar app.
- Text files are read locally; image OCR accepts PNG/JPEG/WebP up to 2.8 MB and sends the chosen image only after AI opt-in + OK. Files are never uploaded just by selecting them.
- Clipboard and microphone require user gestures and browser support. Dictation may use the browser vendor’s speech service; this is disclosed before starting. Stop, closing the bag or minimizing ends dictation.
- Weather queries Open-Meteo for an explicitly typed city; currency uses Frankfurter reference rates, not live trading prices. These two tools need Internet access. They do not request location permission.
- Task progress is represented by a working pose and a hand-held board, with success/dance and error/recovery poses and existing sounds. Local tasks have a brief anticipation phase; Stop cancels pending local work and AI output. Reduced motion uses static poses. The original tour remains available alongside these interactions.

`npm test` includes separate companion tool/browser tests and a server test with a mocked AI upstream. Live provider behavior requires your actual server configuration; it is not covered by the mock.

## Cinematic presence and speech

The same rig now has a shot-staging layer; existing clips, task poses, voice sample clocks and audio buses remain in place.

- `src/cinematic/staging.ts`: deterministic entry vectors, an anticipation hold, a curved approach, scale as depth, gentle distant parallax/defocus and a settling focus spring. Portal restoration and Replay experience restart the approach. Minimize adds a brief arcing shrink into the portal; reduced motion hard-cuts instead. Hero framing is larger; opening the bag stages Jimmy closer beside the panel.
- `src/cinematic/motion.ts`: additive S-line poses, delayed arm/forearm and neck springs, small head/ear/hand/toe offsets. It preserves task hands, existing scene poses and the original ear/tuft/glasses/tie springs. Body poses still update at 24 Hz.
- `src/cinematic/layers.ts`: a shared viewport-space SVG plane masks Jimmy behind marked foreground UI silhouettes during distant shots. Contact/text avoidance remains authoritative. A depth-dependent soft contact shadow and portal ground mark help locate the actor. This is lightweight 2D staging, not a 3D renderer.
- `src/ui/bubble.ts`: organic oval balloon, a short appearance squash, gentle breathing, an independently curved SVG tail behind the actor toward the cheek/mouth region, lagged following and obstacle/edge-aware candidate placement. Text retains a readable minimum scale at a distance. `show` accepts normal, whisper, cheer and thinking styles; the script also selects thinking/cheer from the line. Undo/Okay/Next are integrated as small underlined actions.
- Long tool replies stay in the bag, accompanied by a short “Ik laat het je in de tas zien” line/gesture instead of an oversized paragraph above Jimmy.

Reduced motion removes depth travel, blur, parallax, anticipation, secondary offsets, balloon breathing and spring following. It hard-cuts to a readable pose and keeps the speech tail, tools, clips and optional audio available. No audio cue timing is stretched to match visual depth; entry whooshes are emitted at the launch beat and recorded speech continues on its existing sample clock.

`tests/cinematic.spec.ts` exercises the shot lifecycle, vector selection, portal replay, desktop/mobile balloon bounds and tail geometry, plus live reduced-motion changes. Browser screenshots of the approach and balloon are written to `/tmp/jimmy-depth-*.png` and `/tmp/jimmy-bubble-*.png` for visual review.
